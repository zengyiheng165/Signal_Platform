# 决策树 — AXI DMA 采集链路

> 先判"**全部坏**"还是"**局部坏**"：全部坏看提交/长度/触发；局部坏看长度变化与旧帧复用。
> 每一步都要能指到代码行；取不到证据就写 `未知`。

## 前置门禁：PL 是否已知？

1. 有 `.hwh` / `.xsa` ⇒ 直接读参数（DMA 是否 SG、方向、流位宽、每次数据量），再进下面的现象分支
2. 没有，但用户能口述 ⇒ 按 `SKILL.md` Step 0 的表逐项问清楚
3. 用户也说不清 ⇒ 结论只能写 `未知`，**不要猜 DMA 模式与点数**

## 现象 1：一帧都采不到（每帧超时）

1. 长度一致性：`python scripts/dma_len_check.py ...` ⇒ 不匹配则**永不完成且无错误码**
2. `XAxiDma_SimpleTransfer` 的返回值是否被检查
3. 源 IP 是否真的在产生数据（触发在提交之后？只触发一次还是每帧触发？）
4. 提交前是否 Flush、长度是否按字节

## 现象 2：数据永远不变（波形是一条直线）

1. 给源 IP 换成递增计数/斜坡，确认它本身在更新
2. 触发是否只在初始化时调用了一次
3. 读取的是否始终是同一块缓冲（缓冲指针有没有在切换）
4. 提交前 Flush 的长度是否覆盖整个缓冲

## 现象 3：偶发错帧（读到的不是本帧数据）

1. 超时分支是否继续使用上一帧数据
2. 拷贝边界是否用了缓冲上限而非本帧点数
3. 是否有"某一路没搬完就整体参与运算"的路径

## 现象 4：切换点数 / 切档后失效

1. 传输长度是否为常数（与点数无关）
2. 缓冲区大小是否够新点数（`点数 × 每点字节数`）
3. 是否存在只在默认点数下成立的隐含假设

## 现象 5：只有第一帧，之后不动

1. 提交前是否重新清标志（`RxDone*` 等）
2. 触发是否只在初始化阶段调用
3. 缓冲指针是否一直指向同一块

## 现象 6：部分数据错乱（前几个点 / 后几个点）

1. 触发与提交的先后顺序
2. 拷贝边界、对齐（`TDATA` 对齐要求，按 4 字节）
3. 缓存行对齐与长度是否一致

## 通用规则

- 先判"全部坏/局部坏"，再按现象取证据
- 一次只改一处，改完回读 + 复跑检查
- 结论必须能指到代码行或脚本输出
