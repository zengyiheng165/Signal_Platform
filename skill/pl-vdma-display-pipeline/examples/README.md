# 例子：

> 例子 1、2 可用本技能的脚本验证（改一处、跑一次，再恢复）；例子 3 是显示之外的建议，不影响“能否显示”的判定。

## 例子 1 - 断开 `vtg_ce` 与 `gen_clken`

- **做法**：在 Block Design 里把 `v_axi4s_vid_out` 的 `vtg_ce` 与 `v_tc` 的 `gen_clken` 断开（或改接常量），重新生成 `.hwh`。
- **现象**：**什么都显示不出来**；而分辨率、时序、位宽、时钟在审计里全部正常。
- **判据**：`python scripts/vdma_config_audit.py --hwh <bd>.hwh` 的 **E7** 会报"`vtg_ce` 没有任何连接"；重新接上后 E7 显示"已连到 `gen_clken`"。
- **结论**：参数类审计发现不了连线缺失（E7 是唯一能发现的一项）。

## 例子 2 - 面板是 RGB565，链路里却只有 `v_axi4s_vid_out`

- **做法**：面板按 16bit（RGB565）接线，链路里只有 `v_axi4s_vid_out`、没有转换 IP。
- **现象**：颜色错、位宽错位，看起来像"花屏"。
- **判据**：`python scripts/vdma_config_audit.py --hwh <bd>.hwh --panel-format rgb565` 会报 **E8**（`vid_out` 只支持等宽分量，出不了 5/6/5）。
- **结论**：需要自写转换 IP（24bit RGB → 16bit 565 并生成 DE/HS/VS），或在后面加转换环节。

## 例子 3 - 屏幕是电容式触屏：建议引出一路 EMIO I2C 来配置触摸

- **背景**：面板带电容触摸（触摸控制器挂在 I2C 上），显示已经能出图，但触摸还没接。
- **建议做法**：
  1. 在 Zynq PS 配置里把某一路 I2C 设为 **EMIO**（不是 MIO）；
  2. 在 Block Design 里把该 I2C 接口引到顶层；
  3. 在约束里把 SCL / SDA 分配到扩展口对应的管脚；
  4. PS 端用 `XIicPs_*` 驱动这一路 I2C 与触摸控制器通信（读设备地址、读坐标寄存器）。
- **为什么走 EMIO**：屏幕的触摸排线一般接在 PL 侧的扩展口，而 PS 的 MIO 管脚往往已经分给别的外设；
  把 I2C 切到 EMIO 才能引到那块排线上。
- **边界**：这是**显示之外**的附加步骤，**不影响“能否显示”的判定**；PS 配置、BD 与约束的改动由用户在 Vivado 里完成（本技能不改 PL）。
- **验证**：先确认出图正常，再单独验证触摸（能否读到触摸控制器的设备地址与坐标变化）。
