# 决策树 — VDMA 显示通路

> **第一件事：问屏幕参数**（像素格式 / 分辨率 / HFP-HSW-HBP / VFP-VSW-VBP / 极性 / 像素时钟）。
> 没有这些，`v_tc` 的 8 个参数算不出来、RGB 格式也定不了 ⇒ 只能给排查方向，不能下结论。

## 前置：面板信息是否已知？

1. 已知（像素格式 / 时序明细 / 极性 / 时钟）⇒ 往下判
2. 未知 ⇒ 先问用户，缺什么问什么，记为"未知"

## 现象 1：全黑 / 无信号 / 显示器报"超出范围"

1. **E7**：`vtg_ce` 有没有接到 `v_tc` 的 `gen_clken`（最容易漏，参数全对也会全黑）
2. **E2**：`v_tc` 是否存在、`HFRAME>HACTIVE`、`VFRAME>VACTIVE`、是否逐行
3. **E6**：VDMA 有没有 AXI-Lite 基地址（没有 PS 无法启动）
4. **E5**：`C_USE_FSYNC=1` 时有没有 fsync 源

## 现象 2：花屏 / 颜色不对 / 红蓝互换

1. **E3**：`TDATA` 与分量位宽是否满足 `TDATA = 分量×3`
2. **E8**：面板是不是 RGB565（`v_axi4s_vid_out` 不支持 565）
3. 下游是否把 24bit 按 32bit 解释

## 现象 3：画面偏移 / 压缩 / 黑边 / 不识别

1. `v_tc` 的 8 个参数是否按**面板手册**算（用 `scripts/vtc_timing_calc.py` 反推比对）
2. 同步位置是否落在消隐区、脉宽是否 ≥ 1
3. 4 个极性位是否与手册一致

## 现象 4：画面停住 / 只有第一帧

1. **E1**：MM2S 是否使能
2. **E5**：fsync 源是否在、频率是否等于帧率
3. PS 是否在持续写帧缓冲（属 PS 侧，本 Skill 不覆盖）

## 现象 5：能显示但偶发撕裂 / 局部闪

1. `C_NUM_FSTORES` 是否为 1（单缓冲）
2. 带宽占比是否过高（帧字节 × fps 与 `M_AXI` 位宽对比）

## 现象 6：改了参数但没变化

1. 是否重新生成了 `.hwh` / bitstream
2. 审的是生成产物，还是 GUI 里的旧值

## 通用规则

- 结论必须能指到 `.hwh` 行号
- 一次只给一处最小修改
- 不改 PL，只给"改什么、改成多少"
